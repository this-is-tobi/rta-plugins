# AGENTS.md

Guidance for AI coding agents (and anyone using one) working in this repository — the eleven first-party plugins for [rta](https://github.com/this-is-tobi/rule-them-all), and the index rta installs them from. Each plugin is a separate Go module written against rta's public SDK (`pkg/plugin`, `pkg/sdk`, `pkg/view`, `pkg/format`) and nothing else; rta's [Writing a plugin](https://github.com/this-is-tobi/rule-them-all/blob/main/docs/40-plugins/20-writing-a-plugin.md) is the contract.

## Priority order

1. Security fixes and bug fixes before any new feature.
2. Investigate the cost, benefit and implications of a new capability — and say so — before writing code for it.
3. Every capability draws the read/write line where the others do: the read tier describes the thing, and anything that returns a value somebody stored is a write.
4. Watch binary size: each plugin is its own binary, and a dependency added to one is paid by everyone who installs it. Measure before and after.
5. Everything battle-tested: run `make ci`, and don't report something as working without having run it.

## Git workflow

- Never mention AI, an agent, or a specific AI tool in a commit message or PR description.
- Conventional Commits, enforced in CI. release-please assigns a commit to a plugin by the files it touches, so a commit that touches two plugins releases both — keep commits to one plugin unless the change genuinely spans them.
- Commit locally as normal. Never `git push`, open a PR, or suggest either without an explicit go-ahead.
- Changes to `.github/workflows/*`, `release-please-config.json` or the `release` and `index-release` Makefile targets get an explicit review before even a local commit: this pipeline is what would ship a compromised plugin, and it also writes the index every install verifies against.
- Before any command that could discard uncommitted work, run `git status` first.

## Code style

- No comments explaining *what* code does. When the *why* is genuinely non-obvious, write it at whatever length it takes — the plugins' own comments are the calibration.
- Errors are `*view.Error`, named by a dotted code, addressed to whoever can act on the message.
- Match the existing plugins before introducing a new pattern.

## Before implementing

- The SDK is pinned in every go.mod. `make dev RTA_DIR=../rule-them-all` points a workspace at an rta checkout for an edit loop; `make dev-off` removes it. A `replace` never lands in a go.mod — `make ci` refuses one.
- `plugins/*.yaml` is generated by the release pipeline from the released binaries. Never edit a manifest by hand; a manifest that disagrees with its artifact fails somebody else's install, naming this index.

## Verifying changes

- `make ci` runs what CI runs. Capture its exit code directly — `make ci > log 2>&1; echo $?`.
- No heredocs for generating file content.
